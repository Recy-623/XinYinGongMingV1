# 心印共鸣

本地优先的 AI 关系角色聊天桌面应用，支持本地 Ollama 与兼容 OpenAI 的云端 API。当前版本为 V5.2。V5 的核心功能是“刻舟求剑”：把角色冻结在真实聊天的某个历史切片，从那里建立不会覆盖现实的平行分支。

## V5：刻舟求剑

- 蒸馏时生成最多 8 个带精确消息时间的历史锚点；锚点只保存摘要和当时认知，不保存聊天原文。
- 每个历史切片分别保存当时的人格、关系、已知记忆、称呼、边界和未解决话题，早期分支不会读取最终人设或后期事件。
- 支持“历史约束”“自由改写”“情感重演”三种模式，同一锚点可以创建多个相互独立的分支。
- 真实现在、各个分支的聊天记录彼此隔离；删除或清空分支不会修改原始历史。
- 分支始终标记为模拟，不代表现实中的对方会作出相同回应，也不会替代现实中的同意、承诺或边界。
- V4/V3 角色卡可以迁移，但旧卡缺少历史切片，只会生成一个不可用于回到过去的“迁移时刻”。要使用可靠的历史分支，需要重新导入聊天记录进行 V5 蒸馏。

### V5.1：管理闭环

- 主页可以删除当前选中的角色；确认框会明确列出真实现在消息、时间分支和分支消息数量。
- 删除角色会同时删除其本地头像、人设、聊天和全部分支，并安全切换到相邻角色；不会影响其他角色。
- 时间分支可以重命名和单独导出。导出的分支包含锚点切片和模拟对话，但不包含角色的真实现在聊天或最终人设。

### V5.2：重新选择的闭环

- 可以从任意分支保留前 N 轮用户对话，派生一条独立新分支；原分支不被覆盖。
- 可以在本地比较两条分支的共同消息前缀、模式、轮数和首次不同选择，不调用任何模型。
- 分支导出格式为 `xinyin-branch-v5.2`，带有模拟声明。该文件包含完整分支对话，属于私人数据，请勿提交到源码仓库或随意分享。

## 数据与隐私

- 角色、头像和聊天记录保存在应用 WebView 的本地存储中。
- API Key 只保存在当前运行的内存中；关闭应用后需要重新输入，备份文件也不会包含它。
- 可从控制台导出完整备份或不含聊天记录的角色卡。
- 单分支导出会包含该模拟分支的聊天记录；导出前界面会提示用户自行保管。

## 从微信或 QQ 创建关系角色

1. 在模型区域连接本地 Ollama，或验证兼容 OpenAI 的云端 API。
2. 点击“从微信 / QQ 聊天记录创建关系角色”。
3. 微信可以连接用户自行安装、初始化的 `wx-cli` Windows EXE；QQ 可以检测本机 `qq-chat-exporter`，也可以直接选择其导出的 JSON。
4. 确认哪一个发言者是自己、哪一个是对方；可选“朋友”“暧昧 / 关系未定义”“恋人”等关系预设，或填写自己的相处偏好。
5. 审阅人格、聊天可证实的关系状态、关系预设、相处模式和共同故事后再创建角色。

关系预设用于告诉模型“希望以怎样的分寸继续相处”，不是关于现实关系的事实证明。尤其选择“暧昧 / 关系未定义”时，模型会保持温和、有分寸、可拒绝的表达，不会把单方好感或预设自动写成双方已确认恋爱，也不会替代现实中的同意与边界。

心印共鸣不内置、下载或更新第三方导出工具，不执行 `wx init`、不主动提权、不读取数据库密钥，也不控制 QQ/NapCat 登录。微信连接器只执行固定的 `sessions --json` 和 `history ... --json` 只读命令；QQ 连接器只检测 `127.0.0.1:40653`，实际导出仍由用户在 qq-chat-exporter 中完成。

第三方工具属于独立信任边界：`wx-cli` 可能维护自己的数据库密钥和解密缓存，`qq-chat-exporter`/NapCat 可能持有 QQ 登录状态。详细边界见 [SECURITY.md](SECURITY.md)。

原始聊天只在导入过程中读取；角色卡保存经用户确认的蒸馏结果、关系预设与来源统计，不保存整份原文。角色卡会将“用户的相处偏好”与“聊天可证实的关系状态”分别保存，避免把偏好固化为事实。使用本地 Ollama 时记录不会离开电脑；使用云端模型时，抽取的聊天片段会发送给用户配置的 API 服务。

### 已解密 QQ Android NT 快照（高级）

仓库提供 `scripts/qq_nt_export.py`，用于把用户自己拥有、已经在应用之外解密并复制出的 QQ Android NT `nt_msg` 数据库快照转换为心印共鸣可直接导入的 JSON。脚本不会连接正在运行的 QQ，不会获取登录状态、推导密钥或解密数据库。

```powershell
python scripts\qq_nt_export.py `
  --database D:\path\to\nt_msg.decrypted.db `
  --self-uid <自己的 UID> `
  --peer-uid <对方的 UID> `
  --self-name "我的昵称" `
  --peer-name "对方昵称" `
  --output D:\path\to\chat-xinyin.json
```

脚本以只读模式查询复制出的快照，限制单次读取规模和字段长度，输出只包含平台、参与者统计以及 `sender`、`time`、`content` 三个消息字段。UID、原始二进制、数据库密钥、登录状态和可点击链接不会写入结果。请勿把 QQ 正在使用的数据库文件直接交给脚本。
