# 用户准备与交接

## 用户需要做的事情

1. 在手机和电脑上登录同一个 QQ 账号。
2. 让两台设备处于可信、稳定的同一局域网。
3. 在手机 QQ 的“聊天记录备份与迁移”中选择备份到电脑，并在电脑 QQ 上确认接收。
4. 等到 QQ 明确显示备份完成，中途不要退出 QQ、断网、关机或移动备份文件。
5. 找到电脑上的备份目录，保留原目录结构，不重命名内部文件。
6. 保持电脑 QQ 可用。密码、短信验证码、二维码和设备确认始终由用户本人处理，不发送给 Codex。

不同 QQ 版本的入口文字可能略有差异。若找不到入口，让 Codex查看当前界面或查阅 QQ 当前官方说明，不要随意下载非官方“聊天导出器”。

## 完成后发给 Codex

复制下面文字，补全尖括号内容：

```text
我的手机 QQ 聊天已经通过电脑 QQ 备份完成。
备份绝对路径：<例如 D:\QQBackup\某个备份目录>
要处理的联系人备注/昵称：<联系人>
我的显示名：<聊天中希望显示的名字>
心印共鸣路径：<项目目录或 EXE 绝对路径>
本地 Ollama 模型：<例如 qwen2.5:32b>

我确认这些记录属于我有权访问的数据，并允许创建 MuMu 独立实例、安装官方 QQ、在本机恢复备份、制作只读快照并导入心印共鸣。遇到登录、扫码、验证码或设备确认时停下来让我亲自完成。
```

只有在电脑上存在多个 QQ 备份且无法区分时，才补充 QQ 号。不要发送密码、验证码、二维码截图、设备锁密码、数据库密钥或会话令牌。

## Codex 会在哪些地方暂停

- 模拟器 QQ 首次登录、扫码、短信验证或设备确认。
- 多个联系人同名，无法仅靠本地只读证据确定目标。
- 需要安装此前未授权的高权限工具，或安全边界发生变化。
- QQ 版本或数据库格式不兼容，继续操作可能破坏数据。

除此之外，Codex 应在已授权范围内继续完成恢复、快照、解析、导入、角色创建和聊天验证，不让用户重复确认相同事项。

## 用户最终会得到什么

- 指定联系人的心印共鸣 JSON，而不是整个账号的明文数据库转储。
- 一份不含聊天正文和凭据的导出统计与校验报告。
- 心印共鸣中的角色草稿或正式角色，以及一次本地模型聊天验证结果。
- 原始备份保持不变；模拟器实例、快照和导出文件不会在未获批准时自动删除。
