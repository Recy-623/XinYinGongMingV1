# QQ 聊天备份恢复与角色蒸馏

把用户已经备份到电脑的手机 QQ 聊天，在明确授权和本地处理的前提下，恢复到隔离模拟器、制作一致性快照、导出指定联系人的消息，并交给心印共鸣创建角色。

## 开始前

始终先阅读：

- `references/user-handoff.md`：用户需要完成什么，以及何时通知 Codex。
- `references/safety.md`：授权、隐私、凭据和工具边界。

用户准备完成后，再阅读 `references/workflow.md` 并执行完整流程。

## 工作约定

1. 先做只读预检，确认备份、磁盘空间、模拟器、ADB、Ollama 和心印共鸣路径。
2. 安装软件、创建模拟器实例或恢复备份前需要用户明确授权；本任务上下文已经授权时不要重复询问。
3. 仅在密码、扫码、短信验证码、设备确认等必须由用户本人操作的节点暂停。用户说“已登录”后直接继续。
4. 原始 QQ 备份始终只读。只在带时间戳的工作副本上恢复、合并 WAL、解密和解析。
5. 默认只处理一个明确指定的联系人，并默认使用本地 Ollama；未经额外授权不上传原始聊天、数据库或导出 JSON。
6. 如果唯一可行方案需要进程注入、读取 QQ 进程内存、Root 用户的实体手机、关闭 SELinux/杀毒软件/防火墙、导出登录凭据或安装常驻服务，立即停止并解释原因。

## 执行流程

### 1. 判断用户所在阶段

- 尚未备份：只给出 `references/user-handoff.md` 中的手机到电脑备份步骤。
- 已有备份路径但尚未授权：展示交接模板，并一次性请求所需授权。
- 已授权但模拟器 QQ 未登录：完成环境准备，在登录界面暂停。
- 用户说“已登录”：从恢复备份继续到导出、导入、角色创建和聊天验证，不再重复询问登录状态。

### 2. 运行只读预检

```powershell
powershell -ExecutionPolicy Bypass -File scripts\preflight.ps1 `
  -BackupPath "<QQ 电脑备份绝对路径>" `
  -XinYinPath "<心印共鸣项目或 EXE 路径>"
```

预检不修改文件。缺少依赖时先报告发现，再决定是否需要安装或修复。

### 3. 准备隔离模拟器

创建或复用专用 MuMu 独立实例，不使用用户日常实例。只从可信官方来源安装 QQ，验证包名、版本和文件哈希。所有 ADB 命令必须绑定到该实例，不能误操作实体设备或其他模拟器。

### 4. 由用户本人登录并恢复

让用户本人完成账号密码、扫码、验证码和设备确认。随后通过 QQ 官方的聊天记录备份/恢复入口，把电脑备份恢复到模拟器。以 QQ 界面显示“恢复完成”和目标会话可见作为完成证据。

### 5. 制作一致性数据库快照

等待 QQ 写入完成，正常退出或强制停止模拟器内 QQ，然后复制 NT 消息数据库及同目录的 `-wal`、`-shm` 文件。记录文件大小、修改时间和 SHA-256。原始备份和模拟器源文件均保持不变。

### 6. 必要时离线解密

先判断工作副本是否已经是普通 SQLite。只有确实加密时，才可使用经过审阅的离线工具处理复制出的快照。密钥不得写入日志、截图、脚本、命令历史或最终报告。若只能通过进程注入、内存扫描或安全绕过取得密钥，则停止。

### 7. 导出指定联系人的心印 JSON

对已经解密的只读工作数据库运行：

```powershell
python scripts\qq_nt_export.py `
  --database "<nt_msg.decrypted.db>" `
  --self-uid "<自己的内部 UID>" `
  --peer-uid "<联系人的内部 UID>" `
  --self-name "<自己的显示名>" `
  --peer-name "<联系人的显示名>" `
  --output "<contact-xinyin.json>"
```

校验消息总数、时间范围、发送者映射、解析失败数和输出格式。不得在终端或最终报告中打印聊天正文、内部 UID、密钥、URL 或二进制内容。

### 8. 在心印共鸣中蒸馏角色

导入 JSON，确认“我”和“对方”没有颠倒。默认连接本地 Ollama；30B 至 40B 模型优先从 `num_ctx=8192` 开始，并采用约 800 条均匀时间采样，先生成可审阅的角色草稿。用户确认人物边界和敏感内容后再创建正式角色。

### 9. 验证继续相处链路

进入新角色聊天，发送一条不泄露隐私的测试消息，确认本地模型能回复、角色身份正确、对话风格来自已授权记录且不会把历史推断冒充事实。

## 完成标准

- QQ 明确显示备份恢复完成，目标会话可见。
- 数据库快照包含必要的 WAL/SHM，并有哈希清单。
- 已匹配目标联系人，导出统计和身份方向均正确。
- 角色已创建且可以进入聊天，本地模型能正常回复。
- 最终报告只包含路径、计数、时间范围、哈希和验证结果，不包含聊天正文、账号、UID、密钥或登录数据。
