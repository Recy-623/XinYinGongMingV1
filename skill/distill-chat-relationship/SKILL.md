# 聊天关系蒸馏

从用户明确授权的双人聊天中提取关系结构与稳定相处方式，固定交付三项结果：

1. 一句话关系判断。
2. 带具体时间、变化概括、证据强度与替代解释的转折时间线。
3. 不含聊天原文、可直接导入心印共鸣的 `xinyin-card-v4` 角色卡。

## 开始前

必须完整阅读：

- `references/privacy.md`：授权、隐私模式、内容最小化和停止条件。
- `references/analysis-rubric.md`：关系分类、转折判定和置信度标准。

生成角色卡前再阅读 `references/xinyin-card-v4.md`。

## 工作流程

### 1. 确认输入和隐私模式

- 确认记录属于用户本人有权访问的会话，且目标是明确的一名联系人。
- 明确“我”和“对方”的发送者映射；不得根据语气、性别或昵称猜测方向。
- 用户要求本地处理时，不把正文交给当前 Codex 或云端模型；使用已授权的本地模型，无法满足时停止并说明。
- 用户明确要求 Codex 直接分析时，先说明必要的匿名片段会由当前 Codex 会话处理，然后只读取代表性窗口。
- 原文件始终只读；不要覆盖、移动或删除。

### 2. 只读预检

先运行元数据模式，不输出正文：

```powershell
python scripts/prepare_chat.py `
  --input "<聊天文件>" `
  --self-name "<我的发送者名称>" `
  --other-name "<对方发送者名称>" `
  --metadata-only
```

检查参与者映射、消息数量、时间范围、排序、群聊混入、导出截断和重复。身份方向不能确认时暂停，不开始关系推断。

### 3. 生成最小分析包

分析包只包含匿名统计和少量代表性窗口，不生成完整的标准化聊天副本：

```powershell
python scripts/prepare_chat.py `
  --input "<聊天文件>" `
  --self-name "<我的发送者名称>" `
  --other-name "<对方发送者名称>" `
  --output "<带时间戳工作目录>\analysis-bundle.json"
```

脚本会隐藏参与者姓名、URL、长数字、设备路径和媒体载荷，并从初识、月度阶段、长空窗重连、高信号关系词和结尾阶段选择窗口。日志只能输出计数、日期、路径和哈希。

若自动窗口不足以解释一个疑似转折，只额外读取该日期前后的最小上下文；不要顺手展开整段聊天。

### 4. 形成关系判断

按照 `references/analysis-rubric.md` 同时检查互动频率、合并短句后的互惠、主动性、话题广度、陪伴与优先级期待、冲突修复、长空窗重连、现实承诺和反证。

一句话必须使用：

`最可能是「关系标签」：一句证据概括；对更亲密标签的主要保留是……（置信度：0–100%）。`

关系标签描述观察结果，例如“高亲密线上朋友 / 情绪陪伴型搭档”，不要为了迎合用户强行选择“暧昧”或“恋人”。

### 5. 提取转折时间线

列出 3–8 个真正改变关系状态的时间点，不要把每个热闹日期都叫转折。每项必须包含：

- 具体日期或可核验时间范围。
- 转折前状态、可观察变化和转折后状态。
- 关系影响、置信度和至少一个替代解释。

优先选择初次深化、首次降温、强重连、关系确认或边界重置、冲突与修复、主动性错位、长期沉寂、以新功能重新联系。

不得在最终报告复述聊天原句、账号、UID、链接、密钥或媒体路径。

### 6. 生成蒸馏档案和角色卡

先根据 `references/xinyin-card-v4.md` 创建 `distilled-profile.json`。严格区分：

- `relationshipSummary`：聊天能证实的关系。
- `relationshipEvidence`：阶段、摘要和 0–1 置信度。
- `relationshipPreset`：用户希望的相处偏好；用户未明确选择时必须为 `unspecified`。
- `personality`、`speechStyle`、`interactionPatterns`：跨时间稳定模式。
- `boundaries`、`uncertainties`：防止冒充、越界和把推断当事实。
- `memories`：事件摘要和情绪意义，不复制原句。

生成卡片：

```powershell
python scripts/build_xinyin_card.py `
  --profile "<distilled-profile.json>" `
  --output "<联系人>-xinyin-card-v4.json"
```

如果心印共鸣源码可用，再调用项目自身的 `readCard` 做兼容校验；否则使用脚本内置校验。确保 `history` 为空，卡片不包含原始消息数组。

### 7. 交付

最终回答按顺序给出：

1. 一句话关系判断。
2. 转折时间线表格。
3. 最强支持证据、反证和不能判断的内容。
4. 可点击的角色卡绝对路径、版本、大小、SHA-256 和导入验证结果。
5. 本次语义审阅覆盖量与全量消息数，避免把抽样说成逐条全文审阅。

## 完成标准

- 双方方向已经明确验证。
- 结论包含证据边界和置信度。
- 每个转折都能追溯到具体日期或范围。
- 明确区分事实、推断、用户偏好和不确定性。
- 角色卡为合法 `xinyin-card-v4`，`history` 为空且能被心印共鸣读取。
- 原始聊天未被修改，最终报告和角色卡不含聊天正文、账号、UID、URL、登录数据或本地媒体路径。
