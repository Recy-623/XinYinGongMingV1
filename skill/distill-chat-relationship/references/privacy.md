# 授权与隐私边界

## 授权

- 只处理用户本人有权访问的聊天记录。
- 默认只分析一对一会话和一个明确联系人。
- 群聊、第三方私聊、登录数据或其他账号内容不在默认授权范围内。
- 必须由用户确认“我”和“对方”的映射；不能从语气或昵称猜身份。

## 处理模式

### Codex 直接分析

用户明确要求当前 Codex 执行蒸馏时，可以读取经过匿名和最小化选择的代表性窗口。开始前说明这些必要片段会由当前 Codex 会话处理。不要读取无关联系人或整份媒体目录。

### 本地限定

用户说“仅本地”“不上传”“只用 Ollama”时，聊天正文不得进入当前 Codex 或云端模型上下文。只运行本地脚本和已授权本地模型；如果无法在本地完成语义判断，停止并报告限制。

## 数据最小化

- 原文件只读，不覆盖、不移动、不删除。
- 内部分析包不保存完整标准化聊天，只保存统计和少量匿名窗口。
- 将发送者替换为 `self` 和 `other`。
- 隐藏账号、UID、长数字、URL、设备路径、媒体文件名、Base64 和二进制载荷。
- 角色卡只保留稳定模式、关系摘要、时间线记忆、边界和不确定性；`history` 必须为空。
- 最终回答不复述聊天原句或能定位第三人的独特细节。

## 推断边界

- 玩笑、亲昵称呼、频繁陪伴、吃醋或游戏绑定都不是双方确认恋爱的充分证据。
- 单方好感不是共同关系事实。
- 沉默或长空窗不能单独证明决裂；记录缺失、换平台和现实忙碌都是替代解释。
- 不从聊天推断敏感属性、医疗诊断、性取向、违法行为或现实身份，除非用户明确要求且任务确有必要。
- 角色卡不得声称自己是现实中的本人，不得代替现实同意、承诺或边界。

## 立即停止

- 记录归属、授权或目标联系人不明确。
- 无法可靠确认双方方向。
- 输入包含凭证、令牌、数据库密钥、登录二维码或大规模无关联系人数据。
- 用户要求读取受保护账户、绕过安全机制或提取无权访问的消息。
- 唯一可行方案会把“仅本地”数据发送到外部服务。
